Browsteer

Claude Code can work in this browser when you hand it this key and unlock the door

The key names this browser. Claude Code reaches it through a bridge running on this computer, and only while you have allowed access, on sites you have allowed.

Checking the bridge…

Set it up

  1. Add the bridge to Claude Code

    Run this once in a terminal, from the folder where you cloned Browsteer. It needs Bun 1.3 or newer.

    bun install && claude mcp add -s user browsteer -- bun run "$(pwd)/bridge/mcp.ts"

  2. Start Claude Code

    The bridge starts with the first session and keeps running. The lamp above turns green when this browser has found it; there is nothing to click here.

  3. Allow access, and the site you want help with

    Open the page you want Claude to work on, click the Browsteer button in the toolbar, then choose Allow Claude for 1 hour and Allow for that site. Access closes by itself when the hour is up.

  4. Give Claude the key and a task

    Paste this into Claude Code and finish the sentence. The popup has the same command.

    /browse bst-····-····-···· summarise the page I have open

    What it can see, and where that goes

    While access is on, Claude Code can read and operate pages on allowed sites, using the sessions you are signed in to. Treat the key like access to this browser profile.

    Page contentSent only to the bridge at 127.0.0.1:8787 on this computer, and only when Claude Code asks for it. The extension itself contacts no server.
    ClaudeWhat the bridge returns becomes part of your Claude Code conversation, under the same terms as anything else you show Claude.
    One site per sessionA session stays on the site it started on. If a page tells Claude to go and do something elsewhere, the request is refused. Let Claude switch site in the popup lifts this once.
    PasswordsThe contents of password fields are never sent. Text Claude types into fields is not kept in the bridge's log.
    Risky buttonsButtons that sound final, such as delete, pay, send or sign out, and buttons with no label, are not pressed until Claude has asked you.
    Request logThe address, method and status of the last 300 requests sent to allowed sites while access is on, kept in memory so Claude can find a page's own data source. No request contents. It clears when the browser restarts.
    Semantic targetingOff unless you turn it on in the bridge. When on, an outline of the current page goes to TypeSafe to locate controls by description.
    Stored in the browserThe pairing key, these settings and the last element you picked. Nothing else.
    DialogsWhile Claude is working in a tab, the page's alert() boxes are answered automatically and their text passed on. Confirm and prompt dialogs still wait for you unless Claude was told how to answer. At all other times dialogs behave as normal.

    Where it does not work

    Browser pages such as settings and the extension store, and tabs that were already open when the extension was installed. Reload those tabs once.

    To stop at once, choose Stop now in the popup. New key ends any paired session for good. To stop the bridge: bun run hub:stop.
